# flight-pay-order ref

## flight_pay_order

对已创建的订单发起支付，**永远不自动支付**，必须经用户明确确认。

### 何时使用

订单已创建（`flight_create_order` 成功），用户明确要求支付时。

### 支付前确认

调用 `flight_pay_order` 前，重述：

- 订单号
- 支付金额
- 支付方式
- 当前订单状态（已知时）

如果支付方式未知，先请用户选择或确认支付方式；不要自动填入任何默认支付方式。

面向用户提示支付方式时，不展示余额支付，也不要把余额支付列为可选项：

- 国内机票：可选微信、支付宝、信用卡、借记卡
- 国际机票：可选 Airwallex、微信、支付宝、信用卡、借记卡

用户选择支付方式后，内部映射到工具支付渠道：

| 用户说法 | 工具渠道 |
|---|---|
| Airwallex | `airwallex` |
| 支付宝 | `yeepay-alipay` |
| 微信 | `yeepay-wechat` |
| 信用卡 | `yeepay-credit-card` |
| 借记卡 | `yeepay-debit-card` |

如果用户要求余额支付，不直接执行；请提示当前可选的用户支付方式，并让用户重新选择。

询问：
> 确认支付 ¥xxx，订单号 xxxxxx？

**只有用户明确确认后**才发起支付。

### 异常情况处理

出现以下任一情况，**先调用 `flight_order_detail` 核查状态**，再决定是否重试支付：

- 支付金额与预期不符
- 订单状态不明确
- 上一次支付可能已在处理中
- 订单可能已失效，或支付/出票截止时间缺失、已过期、含义不清

### 第三方支付

第三方支付链接（`returnUrl`）不要求普通用户理解其含义，使用已配置的默认值。

### 支付后

支付完成后，使用 `flight_order_detail` 核查或展示订单状态，说明最终出票状态取决于工具返回的订单状态。

### 错误处理

支付失败时：

1. 简短说明失败原因
2. 调用 `flight_order_detail` 核查当前订单状态
3. 再决定是否重试，不盲目重试
